## 1. Scope

Wave 0 is the audit's one line for this week: "what harms a learner today. All are sentence-, listing- or key-sized." It covers:

- **The way in:** the placement, Today and Boot fixes in the learner app, and the serving-first warning.
- **Wrong and graded:** the factual errors a learner is graded on, and the sims whose graded tasks repeat them.
- **Wrong and acted on:** the errors a learner is likely to act on, and the appendix rows whose fix is a sentence.
- **Broken rendering**, the signposts for an older course with their CI check, lab text, and the paper link in t2.l7.
- **The dated job:** re-pin vLLM from v0.31.0 to v0.34.0 and fix the course's 16-token claims once, before 2026-12-04 (section 5).

Wave 0 is not:

- a change to any lesson id, track order, path, ring, grading rule's meaning, or the set of lessons;
- a new block type, a new simulator mode, a new section or lesson, a CI workflow change, or a rebuild;
- a re-pin of the price claims, or the Wave 3 claim watcher;
- anything that needs a GPU or a learner (section 8).

## 4. Rules every task carries

- **Where to work.** Each task works in its own worktree of origin/master d478f91 with a private `node_modules`. Task branches are `k0/<task id lowercase>`; they merge into the integration branch `wave-k0`. Nobody edits the owner's working tree.
- **The gate.** From a pristine export of the commit, with bun in CI mode: `npm run lint` (bare, never piped); every `verify:*` script in the repository's list; `npm run build` and `bun run verify:bundle`; the export freshness check for `public/lessons-md` and `public/llms.txt`; and the full unit suite. Path-filtered workflows (`labs.yml`, `physics.yml`) run whenever a pull request would trigger them. Playwright specs named in a task's acceptance run in that task's own gate.
- **Frozen numbers.** Listed in section 2 (K0-Z-D6). A failing gate is fixed by changing the change, never by changing the gate.
- **Errata.** One module per correction, `src/data/errata/<YYYY-MM-DD>-<slug>.ts`, with an id equal to the file name, a date no more than one day ahead of UTC, a kind of `error` or `changed`, at least one real lesson id, a `why` of at most 40 words, an https source with a title, and at most two single-answer items with a why for every option.
- **Claims.** A number or dated statement a task adds is a claim with a dotted lowercase id, a kind, a value, a unit, a label, a source with a quote for specs and prices, a `verifiedAt` no later than the read date, a `ttlDays`, a boundary, and a `pin` for engine settings, which is never a moving ref. New claims go only into the lazy group K0-D0 created for their lane. `bun scripts/verify-claims.ts --write` regenerates `public/claims.json`. No Wave 0 task adds a derived claim or edits `scripts/verify-claims.ts`.
- **Saved answers.** Quiz, prequestion, diagram and critical-reading items are stored by position with a fingerprint of their stem, options and correct answer. A generator change bumps the family's `version` and moves only that family's hash fixture.
- **Generated files.** Regenerated by their scripts and committed in the task's last commit. After a conflict in one of them, the merge takes the integration branch's side and runs the script again.
- **Tests.** An acceptance item is observable: a test that fails on d478f91 and passes after, a verify script, or a quoted source line with its address and date. A new test goes in a new file named for its task.
- **Commits and pull requests.** Conventional subjects, lowercase type and scope, stating the true thing. Bodies say why. Every commit names its task in a `Task:` trailer. Pull requests carry every source quote with its address and read date.
- **Never.** Edit the owner's files; change a workflow, a toolchain pin or a branch setting; hand-edit a generated file; pipe lint; skip a gate because a stub prints ok; write a number or date into a lesson without a claim; edit an old erratum; send personal details in a request.

## 5. The dated job: re-pin vLLM and fix the 16-token claims (deadline 2026-12-04)

**What lapses.** Eleven claims lapse on 2026-12-04: `production.vllm.{block-size, v1-preemption, scheduling-policy, watermark, max-num-seqs, max-num-batched-tokens}` and `production.sglang.{schedule-policy, schedule-conservativeness, retract, max-running-requests, chunked-prefill-size}`. Seventeen more lapse on 2026-12-13: the eight vLLM field claims, the BurstGPT claims, the EPLB and disagg rows of both engines, Triton's group size, and both twins. A lapse fails no build. Learners see an amber "stale since" in claim popovers, Boot chips, the twin panel and the field labs.

**What moved.** At vLLM v0.34.0 (released 2026-11-16) the default KV block is 64 tokens, where v0.31.0 had 16. The release notes say "Default --block-size is 64 (was 16)". The disagg quote changed. `gpu_memory_utilization` now defaults to None. Every other vLLM quote was found unchanged at v0.34.0. These are the planner's reads of 2026-11-20, recorded in the build plan and not re-verified by this file; each re-pin task re-reads them on its build day and quotes what it reads.

**What the course says.** Nine surfaces type vLLM's default as 16: t5.l5, t5.l6, t1.l3, t1.l4, t2.l7, the glossary, the allocator sim, the block-table explorer and its task. The claim, its physics cross-reference and the KV sim's stand-in boundary also name it.

**The repair.**
- K0-D1 gives lessons a helper that reads a claim's value, release and date.
- K0-D2 registers the paper's 16-token block as its own claim.
- K0-D3 to D10 re-pin vLLM and SGLang and re-read every claim that lapses.
- K0-D11 to D20 make each place say either "the paper's 16" or vLLM's default read from the claim.
- K0-D22 writes two errata: one superseding the 2026-10-05 erratum for the block size, and one for "<4%" (t1.l3, t1.l4, t2.l7, t5.l5).
- K0-D23 fails the build if a typed default returns.

**Timeline.** PR `k0-repin` ready with green gates by 2026-11-28, leaving the owner a week before 2026-12-04. K0-D10 (the non-engine claims) must land by 2026-12-13 but is in the same PR. Each re-pin task's pull request quotes every line it re-read at the tag (file, line, url, read date); that is the proof of the re-pin.

## 8. What the build cannot verify

- **No GPU.** The field labs stay unrun. No engine is run: every engine fact is read from source at a tag, not observed. The roofline, Fleet and physics numbers are not re-measured.
- **No learner.** The audit's first step, watching newcomers on t0.l1, r.l1 and t2.l1, belongs to the owner. Every claim that a change helps a learner is a prediction; the tests show only that the page now says and does what the audit asked.
- **One machine.** Measured figures come from the builder's desktop and are stated as such, good to about 20 per cent.
- **Sources move.** Every quote is true on its read date. Several points stay unsettled in the audit: reading speed (through secondary pages); the released glibc 2.43 tree; whether Dynamo's v1.5.0 notes were edited; the H100's shared-memory bandwidth; and "85-95% shared prefix", which has no source.
- **The live site.** Which build the public site serves was not proven.
- **Nightly-only suites.** The end-to-end and accessibility suites run nightly. The plan requires the builder to run them before the wave merge.
